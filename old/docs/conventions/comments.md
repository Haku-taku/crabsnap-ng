# 注释规范

> `AGENTS.md` §6 的完整版。要点：**英文在前、中文对照；每种语言最多两行。**
> 小节号对应 `AGENTS.md` §6.1–§6.5（旧引用按编号对照）。

## 1. 语言：英文在前，中文作对照

每条注释都是 **英文原文 + 中文参照**。中文是阅读辅助，不是第二份文档——必须一口气读完。

```rust
// Fractional scale makes 1pt -> 1.5px; rounding here would drift the whole tree.
// 分数缩放让 1pt -> 1.5px；在这里取整会让整棵树漂移。
```

- 英文行**必须**有；中文行也**必须**有（团队工作语言）。
- 不要一种语言写一段、另一种语言再翻译一遍。

## 2. 硬上限：每种语言**两行**

一段注释（连续的 `//` 或 `///`）上限是 **2 行英文 + 2 行中文**——四个物理行。
通常形状是每种语言一行；某一种语言用满第二行也可以，超过两行不行。

**注释里不允许写**：文件历史、bug 叙事、重构日志、工单号、"以前我们这么做"、
表格、项目符号列表、堆栈、协议摘录、多段论证。想说的东西超过两行，就不属于代码。

**允许的注释类型：**

| 类型 | 用途 | 例子 |
|---|---|---|
| 为什么存在 / 为什么是这个形状 | 非显然的约束 | `// Must run before commit: the compositor drops late damage.` / 必须早于 commit：compositor 会丢弃迟到的 damage。 |
| 非显然的不变量 | 读者可能静默破坏的东西 | `// Sum == 1.0 by construction; do not renormalize.` / 构造上保证和为 1.0，不要再归一化。 |
| 外部协议/API 陷阱 | 外部强加的约束 | `// zwp_text_input_v3 buffers until "done"; apply nothing before it.` / 该协议在 "done" 前缓冲，之前不要应用。 |

**明令禁止**：复述代码、变更日志式注释（`// 2026-10 changed to X`）、注释掉的代码、
没有 issue 链接的 `// TODO`、超过一行的装饰性分隔线、ASCII art、只重复类型名或函数签名的注释。

## 3. 逻辑超出预算时：一条笔记，加一行指针

复杂逻辑允许有文档——**每个主题最多一条短笔记**，绝不是叙事。代码里只留指针：

```rust
// Effect region must be widened by sample_pad; see docs/notes/effect-region.md
```

**笔记数量要少。** 旧项目有约 200 篇笔记；那是"代码里什么都没定下来"的症状，不是严谨。
把笔记目录当成稀缺资源：

| 规则 | 内容 |
|---|---|
| 预算 | 从**零**开始。每条新笔记都需要一个能过评审的理由 |
| 前提 | 主题必须真的难（协议陷阱、数值技巧、平台怪癖）**且**无法用"测试名 + 两行注释"表达 |
| 长度 | 一屏。需要滚动的笔记是设计问题，不是文档问题 |
| 内容 | 严格四段：症状 → 根因 → 修法 → 如何验证。没有历史、没有备选方案、没有指标表（除非指标就是证明） |
| 维护 | 笔记过期就删。错的笔记比没有笔记更糟 |
| 索引 | `docs/notes/README.md` 列出每篇笔记与一行摘要；新增笔记时同批加一行。目前靠人工对账，没有自动检查 |

**判断"要不要写笔记"的测试**：如果整个不变量能写成一条名字自解释的断言加上两行以内的注释，
那就写测试，不要写笔记。

## 4. 推翻旧项目的决定 → 写 ADR，不写代码注释

与旧项目做法相反的决定需要记录，但记录放在 `docs/decisions/<slug>.md`（ADR 风格），
**不是**代码注释。代码里最多留一行指针。ADR 控制在半页：旧做法是什么、为什么不行、
我们改用什么、哪条检查能抓住回归。

## 5. 用户可见字符串

绝不硬编码。一律走 i18n（Fluent）。注释仍按 §1 双语。
