# ADR: GPU 是主呈现路径，CPU 是可滞后的回退

状态：**已采纳**（2026-10-27，用户决定）。

## 问题

此前两条路径被当作**等价**的：每个场景都要 CPU 与 GPU 逐像素对照，任何图元都要两边同时实现。
这让每一处材质（acrylic、玻璃折射、rim）都变成双份工作，而实际上：

- 项目的目标场景绝大部分是 GPU 呈现（零拷贝 dma-buf）；
- CPU 光栅器随时可能被改动或替换（它只是回退与离屏诊断）；
- 为了让两边"数值一致"，曾多次把注意力从"看起来对不对"转移到"两个实现是否同步"。

用户明确指出：**GPU 是主路径，CPU 回退应该靠后，因为它随时可能变化。**

## 决定

1. **GPU 是主路径**。材质与效果（背景模糊、tint、噪点、折射、rim）只在 GPU 侧实现。
2. **CPU 侧可以缺席**。缺席时必须显式记账（跳过并计入 `stats`，代码里一行注释指明），
   不得伪造输出，也不得为了让对照通过而退化 GPU 实现。
3. **对照检查收窄**。`gpu_*_scene` 的 CPU 对照只覆盖**两边都已实现**的图元，
   且这份清单必须显式列出（不能用通配），新增图元默认不参与对照，直到 CPU 侧补齐。
4. **不再以"双后端一致"作为正确性的第一判据**。第一判据是 GPU 场景自身的数值断言
   （例如模糊边缘必须变软、环外羽化不得含填充色），CPU 对照只用来抓"GPU 独有"的偏差。

## 为什么

- 一个实现错两次仍然相等：逐字节相等本身没有区分力（`AGENTS.md` §1.5「两个渲染结果逐字节
  相等就说明没残留」）。真正的参考必须来自不复用任何东西的独立实现。
- 材质是外观问题，判据是**画面事实**（边缘软化、羽化纯度、颜色占比），不是另一个后端的字节。
- 双份实现把改动成本翻倍，而 CPU 侧的寿命更短。

## 代价（明说）

- `ui-paint`（CPU）与 `ui-paint-gpu` 会出现**已知的外观差异**，且会持续一段时间。
- 离屏诊断（`PPM` 导出、`toggle_gallery` 的几何探针）仍走 CPU，因此它们**看不到**材质；
  涉及材质的验证必须跑 GPU 场景。
- 若将来把 CPU 提升为正式后端，这份差异清单就是补齐清单；它必须可枚举（见下）。

## 回归检查

- 每个 GPU 场景示例自检输出 `FAIL=0`；破坏对应着色器必须变红。
- 新增图元若 CPU 未实现，`RenderStats` 里要有对应计数，示例输出里能看到"CPU skipped N"。
- `platform_boundary.rs` 的三条边界检查不受影响，仍然强制。
