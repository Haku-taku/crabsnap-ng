# ADR: 控件回落策略（native → synthesized → borrowed）

状态：**已采纳并实现**（2026-10-27，用户决定）。语义与分派在 `ui/crates/ui-widgets/src/`，
每种风格各自成 crate：`ui-widgets-md3` / `ui-widgets-fluent` / `ui-widgets-glass`。

## 问题

同一种功能角色（勾选框、开关、按钮、右键菜单、导航）在 MD3 / Fluent / LiquidGlass 里的
**行为与结构**不同，不只是材质与数值：

- MD3 勾选框是「18dp 方框 + 40dp 圆形状态层 + 涟漪」，载体随选中/错误翻转；
- Fluent 勾选框是「方框自身填充随悬停洗色 + 矩形焦点环」，没有圆形状态层；
- MD3 开关没有标签概念，Fluent 的 `ToggleSwitch` 把标签与开关包在一个控件里；
- MD3 菜单缩放淡入、48dp 行；Fluent 上滑入场、32px 行、跟随指针的高光。

因此**单一套绘制代码不可能实现三者**。但控件体系必须始终可用——应用不能因为切了个风格
就少一半控件。

## 决定

每个功能角色按三步解析，顺序固定：

1. **Native** —— 当前风格确实有这个控件，用它的真实实现。
2. **Synthesized** —— 当前风格没有，就用**该风格自己的令牌**拼一个朴素版本。
   外观是近似的，但配色/圆角/字体/动效都属于当前风格，不会突然跳戏。
3. **Borrowed** —— 连拼都拼不出来（例如需要该风格没有的机制），就从回落链里按**固定顺序**
   借另一个家族的实现。**外观不一致，这是有意的代价。**

另有两条非策略、而是缺陷信号的状态：

- **Broken** —— 家族声称支持某角色却返回空。这是该家族的 bug，必须报出来，不能悄悄降级。
- **Missing** —— 全都没有。给一个占位节点让应用继续运行，并如实标记。

## 为什么这样排

- 合成优先于借用：借用会让同一窗口里出现两种设计语言，视觉上比「朴素但同风格」更糟。
- 借用顺序由调用方固定，而不是按能力挑选：同一应用每次必须解析出同一结果，
  否则外观会随加载顺序变化，不可复现。
- 静默降级被显式排除：`Service` 是可读的返回值，`is_consistent()` 回答「这像素是否符合
  当前风格」。历史上「后端不支持就静默跳过」正是画出看似合理错画面的来源（AGENTS.md §1.5）。

## 代价（明说）

- 三套实现 ≈ 三倍工作量，因此控件集要刻意挑选。
- 有些控件只存在于一种体系（Fluent Ribbon、MD3 NavigationSuite），用到它们就等于放弃
  运行时切换。框架允许这件事，但不假装统一。
- 运行时切换的前提是**应用写语义 API**。一旦直接实例化某个家族的具体控件，切换就不可能。

## 回归检查

- `a_role_the_active_family_lacks_is_synthesized_before_any_borrowing`：
  把借用挪到合成之前立即变红。
- `a_family_that_claims_support_and_returns_nothing_is_reported_as_broken`：
  把「声称支持却返回空」当作不支持吞掉，立即变红。
- `every_role_resolves_for_every_family_in_the_matrix`：任何角色都不得 panic 或丢 id。
