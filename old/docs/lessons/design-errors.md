# 我们自己的设计错误（累积表）

> 从 `AGENTS.md` §1.5 迁出。这张表比「旧项目不信任案例」更重要：**新仓库的设计同样会错，
> 而且错在自己的盲区里。**
>
> **用法**
>
> - 动手改某个子系统前，先扫一遍相关条目：它们是同一批人在同一类判据上踩过的坑。
> - 新增条目必须三列齐全，且「发现方式」是一次**可复现的观测**（测试、探针、像素读数、
>   逐帧 trace），不是"我觉得"。只写结论的条目没有校准价值。
> - 条目**只增不删**。机制被撤除时保留原条目，并在表头注明它描述的是哪个时期的代码。
> - 新条目的门槛（借用 Zed 的 Rules Hygiene）：**非显然**（熟悉本仓的人也会做错）、
>   **重复遇到或代价足够大**、**具体到能照做**。三条不全就不要加。
>
> **教训**：上一张表（旧项目不信任案例）里的错误模式，在自己的设计里同样出现过。
> 所以 `AGENTS.md` §1.2 的三条采信通道对新仓库的设计文档同样适用——
> **设计也要被验证，不能因为"是我写的"就免检。**
>
> 这张表的作用是**校准判断**：已经证明旧项目在这两类事上会错（"接错开关"、
> "分层注释与代码不符"），所以同类说法要加倍核实。

> **历史条目说明**：下表中凡提到「原始背景快照 / `raw` / `raw_valid` / 子块缓存 /
> `frost_carry` / `read_raw_backdrop` / `written()` 上报」的行，描述的是**已于 2026-10-27
> 撤除**的跨帧复用机制。这些 API 与机制已不存在，条目只作为「我们怎么错的」保留；
> 现行契约见 `docs/effect-cache-plan.md` §11 与本表「跨帧复用滤波像素可以逐块记账」一行。

| 说法 | 实际情况 | 发现方式 |
|---|---|---|
| "HDR 存储域必须是 f16，SDR 也要在 f16 渲染再降 8-bit" | 存储域与运算域可以分离。SDR 直接就 `Srgb8`，线性化用 LUT 往返，实测量化误差 ≤2 LSB | 被追问"能否避免域间转换"后重算 |
| "`pad` 由算法算好交给引擎" | `⌈3σ⌉` 是实现选择不是语义。改成 `EffectReach { guaranteed, actual }` | 按"保证 vs 估计"判据扫字段 |
| "CPU 与 GPU 必须数值一致，逐像素比对" | 与同一文档里"AA 不能用逐像素相等"自相矛盾 | 交叉检查同类断言 |
| "布局一趟 measure 就能拿到底" | 尺寸可以一趟算完，但**分配剩余空间必须知道父的最终尺寸**，只能在自上而下的定位趟里做 | 写 `window_hello` 时色块宽度全是 0 |
| "`NodeData::Container` 与 `NodeData::Box` 可以自由组合" | 容器带背景时两者冲突，导致布局不递归、子节点全 0 尺寸 | 渲染出空白图，追踪 rect |
| "字形光栅有非空覆盖率、尺寸随字号变化" = 光栅正确 | 还漏了**相对基线的垂直位置**：`top` 用了错误的一侧，大写字母整体下沉一个 cap height | 用户报告垂直位置异常，用像素扫描量出证据 |
| "测试验证了字形被画出来" | 只测了存在性（非空、随字号缩放），**没测几何正确性**（是否坐在基线上） | 上面那条 bug 就是因为这个才漏掉 |
| "字形位置取整就够了" | 直接丢弃小数部分，累计位移越过整数边界时整像素跳变（实测摆幅 0.844px） | 用户报告「前面字符变宽时后面字符抖动」 |
| "亚像素就是 4 相位光栅化" | 还漏了：**垂直不做**、**CJK 要排除**、**必须在设备空间量化**（分数缩放下逻辑空间量化残留 1px 抖动） | 先读 egui/GPUI 源码才发现这三条 |
| "亚像素做完就锐利了" | 1.6 倍下仍模糊且基线错位：**光栅字号用了逻辑字号、位置用了设备坐标** | 用户第二次报告，逐字段核对单位才发现 |
| "`swash` 的 `direction(RTL)` 会重排字形" | **不会**。两种方向返回同样的逻辑序（cluster source 递增），RTL 段必须调用方自己 reverse | 打印 cluster source 实测，而非相信 API 名字 |
| "`unicode-bidi` 会处理括号镜像" | 明确声明不做 L4；不补的话 RTL 段显示成 `)文本(` | 读源码注释 + 打印字形 id 对比 |
| "两块 GPU 都能导入 dma-buf，所以哪块渲染都行" | 协议层能导入、release 正常，但**显示全黑**；必须渲染在驱动已连接输出的那块 GPU 上 | 双 GPU 真机对比 + 全屏像素扫描 |
| "GPU 渲染完直接提交就行" | 缺 `glFinish` 时 compositor 采样到未完成的写入，窗口全黑；而 CPU mmap 读同一块 bo 却正常 | 同缓冲双探针（GL 读回 vs mmap）对照 |
| "GL 帧缓冲椭圆原点所以要 `1 - y/H*2`" | 对 dma-buf 是错的：GL 第 0 行 == dma-buf 第 0 行 == 图像顶部，应写 `y/H*2 - 1` | 画面整体上下颠倒，靠像素坐标定位发现 |
| "测试全绿 = 验证过了" | 38 个测试用 `fc-match` 取字体样本，Windows 上取不到就**静默 return**，看起来全绿实则空跑 | 交叉编译到 Windows 跑测试时才发现 |
| "13px 下 2 倍缩放的字形高度正好是 2 倍" | 小字号整数取整占主导，换字体后比值变 1.75；测试靠特定字体侥幸通过 | Windows/Wine 下换字体直接变红 |
| "全量跑通过 = 平台没问题" | 并行跑崩（Wine 下并发初始化 DirectWrite），串行 42 全过；只看一次结果会得出相反结论 | 固定线程数做对照实验才分离出并发因素 |
| "fontique 的 `fallback_chain` 给的 FaceId 一定有字体可加载" | 族名可能来自残缺的 fontconfig 索引，`face_data()` 返回 None；字体栈必须按"字节能加载"过滤 | 阿拉伯文回退不出字形，逐层探测到 `face_data` |
| "只有一个通用族就能排所有文字" | 拉丁/CJK/阿拉伯很少同字体覆盖，单一字面整形只得 `.notdef`；必须按段选覆盖字面 | 阿拉伯语渲染成断开且乱序的字母 |
| "`AppLoop` 换到真实窗口就能用" | 缩放后 `copy_from_slice` panic；且绘制快于合成器消费时屏上是旧帧（帧缓冲里却是对的） | 窗口 resize 后崩溃 + 截图与帧缓冲导出对比 |
| "uniform 名字写错，编译期就能发现" | `get_uniform_location` 返回 `None`，`if let Some` 静默跳过，纹理从未绑定；表现为画面拖影 | 层合成采样到残留字形图集，导出层纹理才定位到 |
| "用 `padding` 可以移动元素" | padding 只内缩子节点，**背景与边框留在原地**，看起来像"内容整体偏移" | 先把同样代码放到 CPU 路径对照，确认与后端无关 |
| "圆角要么圆要么不圆，做成枚举即可" | 它是连续参数：CSS `superellipse(K)` 的指数是 `2^K`，命名形状只是预设；一条 Lp 范数公式覆盖全部 | 查 CSS 规范原文，而非二手博客 |
| "`superellipse(K)` 的指数是 `2K`" | **错**。规范原文是 `2^K`；按 `2K` 写，`bevel = superellipse(0)` 会退化成无意义方程 | 对照 W3C 规范正文，发现与博客矛盾 |
| "布局算出了 `mask`，绘制自然就会裁剪" | `paint_tree` 从不发 `PushClip`，`batch.clip` 永远 `None`；子节点直接画到父容器之外 | 40×40 容器放 100×100 子节点，数出 2400 个越界像素 |
| "交叉轴撑满不会影响 `fixed`" | 撑满公式完全无视子节点 `max`，`fixed(100)` 被撑成 160 | 修裁剪后探针仍泄漏，追到更早的布局计算 |
| "GL 的 scissor 原点在左下，所以要翻转 Y" | 本渲染器投影**故意不翻转**（GL 第 0 行 == dma-buf 第 0 行 == 图像顶部），scissor 也必须不翻转；否则裁剪被镜像到另一侧 | 接上裁剪后整行文字消失，靠多高度的裁剪带定位 |
| "0.000002px 的裁剪是无害的" | 它会打断批处理（3 批变 2 批），且会走到从未被执行过的 scissor 分支 | 打印批次数才看到多出来的一批 |
| "裁剪只需要在墨迹溢出时发出" | 圆角裁剪不行：子节点完全在矩形**内**仍可能盖住圆角，因此半径非零且有子节点就要发 | 圆角容器里铺满子节点，角落露出方块 |
| "裁剪矩形可以直接和渲染区域求交" | `batch.clip` 是逻辑单位、`region` 是设备像素，直接求交**只在 scale=1 时成立**；GPU 侧乘了 scale 所以是对的 | 逐处核对单位才发现是单边错误 |
| "两个配置相同的实例行为相同" | 有内部缓存的组件（script→face 缓存）会因状态分叉给出不同宽度，进而断行不同；必须共用同一实例 | CJK 段落布局算 2 行、绘制排 3 行，文字叠到下一行 |
| "绘制端可以从节点矩形推断换行宽度" | 节点宽度可能被父容器撑满，与布局测量用的宽度不同；必须由布局把实际值记下来 | `fixed(170)` 的节点布局按 170 测、绘制按 396 断 |
| "报错的那个调用就是出错的调用" | GL 错误是粘滞的：在 `use_program` 之前设 uniform 报了 `INVALID_OPERATION`，却在下一次 dma-buf 目标创建时才被看到 | 报错指向 `glEGLImageTargetTexture2DOES`，实际无关 |
| "省略号截断从上一行末尾继续填" | 从**第 n 行原本的起点**重新填充；按直觉写测试期望值会错 | `"dd"` 期望 vs `"cc d"` 实际，实现是对的 |
| "布局算出的高度比文本小 = 布局算错了" | 容器装不下全部子节点时会**压缩**子节点；先看内容总高是否超过容器 | `box_h 63.6` vs `text_h 79.6`，实际是 Column 压缩，加大画布即恢复 |
| "示例编译失败时跑的是新二进制" | `cargo build` 失败但旧二进制还在，`cargo run` 会跑旧的；先看构建是否真的成功 | `window_gpu` 编译失败，截图来自上一次的产物 |
| "质量守恒测试失败 = 核没归一化" | 样本太小时 u8 量化噪声会超过容差，冒充算法错误 | 8x8 色块漂移 1.7%，改 24x24 后 <1% |
| "后端不支持的功能静默跳过无伤大雅" | 静默跳过会画出看似合理的错画面；必须报错并说明缺什么 | 定为 `GpuError`，并用示例钉住"必须拒绝" |
| "新建的缓冲已经可以用了" | 记录尺寸时若写的是"请求值"，负责分配的 `if size != want` 分支会被跳过，纹理从未分配 | FBO 不完整，每趟都报 `GL_INVALID_FRAMEBUFFER_OPERATION` |
| "写满每个像素就不用管混合与初始化" | 混合方程会把未初始化暂存的内容混进来；新缓冲要么清空要么关混合 | scratch 未清 + 混合开启 → 整层变白 |
| "模糊会让峰值下降" | 色块比核大时中心仍饱和；定义性事实是**边缘变软** | 判据写错，GPU「失败」而实现正确 |
| "预乘/直通与通道序"（第四次） | 已把它变成 API：`GpuRenderer::to_premultiplied_bgra`，不再靠每个调用方各自推导 | 转错时墨迹总量差一倍以上 |
| "文档里写的已知缺口就是真的" | 未验证的缺口描述会把后来人引到错方向；先 `grep` 字段是否真被引用，再动手 | 「模糊在层边缘被截断」——`bounds` 在两个后端都是 0 处引用，从未截断 |
| "输出变换只需加在正常结束路径" | 静止帧有独立的提前返回路径，绕过变换后 sRGB 值被当 PQ 解码 → 画面发白发亮。修法是把交出点收敛成唯一函数 | 用户报告「静止帧发白」；`grep -c blit_framebuffer` 查出两处 |
| "线性混合与编码域混合的差异在 1 LSB 量级" | 实测 50% 白叠黑：编码域 128，解码后混合 187，差 **59 级**。切换混合域是**外观变更**而非 bug 修复 | 写 `blend_domain_tests` 量出来，而不是继续推演 |
| "`guaranteed` 与 `actual` 是两个值" | 若 `guaranteed` 由 `actual` 反推，它就恒等于 `actual`，区分形同虚设 | `ceil(3 · radius/3) ≡ radius`；根因是 `Kernel` 不记得 sigma |
| "焦点样式写在 `view` 里就会显示" | 回调（`scroll`/`activate`）的返回值被丢弃，app 说"要重绘"没人听，只能等下一个无关事件顺带刷新 | 用户报告「激活计数要下次刷新才更新」；`handled` 只含 `event` 的返回值 |
| "滚轮会落在可滚动的容器上" | 它落在最上面的东西上——一行、一个标签。按原始命中目标路由，app 收到 `row` 而不是 `scroller`，于是什么都不动 | 用户报告「列表无法滚动」；改为沿 parent 链上溯到最近可滚动祖先 |
| "布局装不下就会溢出" | 引擎的规则是「亏空则压向各自下限」：内容被**压缩塞进**盒子，永远不溢出，滚动容器因此无事可滚 | 用户报告「列表只有一行」；查 `distribute` 的亏空分支 |
| "可滚动容器只要平移内容" | 平移之外还必须**允许溢出**（`scrollable`），否则子节点先被压小，平移的就是一坨挤扁的东西 | 同上；`main_avail` 取「测得总量」才既不压缩也不留增长空间 |
| "同一父节点下重复的 `Id` 会报错" | 静默塌成一个节点，六行变一行，只有最后写入的文本存活 | 打印子节点坐标时只输出**一行**；列表项用同一个字符串是最常见的写法 |
| "测试通过就说明它钉住了行为" | 两次：`arrows_move_by_geometry_not_tree_order` 在流式布局下树序与几何一致；滚动路由测试打在 (30,30) 而命中行只占 y 0..22 | 都靠「退回旧代码看是否变红」这步暴露 |
| "`FontRequest` 有 weight/italic 字段，所以字重已经支持了" | 字段从未被读取：`resolve` 每族只登记一个槽位，`face_data` 又永远取 `fonts().first()`。三层缺陷叠在一起，单独修任一层都不够 | 追 `Weight` 的使用点时发现全仓只有定义与导出，没有任何读取 |
| "不同字面必然有不同的字节" | 可变字体是**同一个文件**靠下标区分字面，长度相同完全正确 | 断言先红后查，发现是测试假设错而不是代码错 |
| "从集合里挑一个满足条件的族" | `HashMap` 迭代顺序不是契约，同一构建时绿时红 | 连续跑三次才暴露；改为排序后取第一个 |
| "feature-gated 的测试在默认 `cargo test` 下仍然有效" | `system` 默认关闭，`system_or_isolated()` 返回空集合，测试**静默空转**；开了 feature 才立刻变红 | 故意破坏代码后测试仍绿，才发现它压根没跑 |
| "`Shaper::new(data, 0)` 里的 0 无关紧要" | 集合字体（TTC）把多个字面打进一个文件，永远解析下标 0 就永远画第一个字面；光栅器里还有四处同样写法 | 追字重时发现字面选对了但轮廓没变 |
| "族内下标就是文件内下标" | 槽位记的是字面在**族内**的位置，解析器要的是在**文件内**的位置；混用后 Calibri 粗体又变回常规宽度 | 修完反而退化，才去查 `FontInfo::index()` |
| "宽度不变就是字重没生效" | CJK 字体在任何字重下前进宽度都相同，宽度无法判断可变轴是否生效 | MiSans VF 宽度 189.92 vs 189.74，但光栅覆盖率确实不同；改为比像素 |
| "按 `units_per_em` / 某个字符的字形判断两个字面是否不同" | Cambria Math 的 #1 与 #0 度量相同、`A` 的字形也相同，这个判据**永远无法区分**；而且第一版还因选到该族而恒红 | 改成比「一组字符的光栅覆盖率」，并验证破坏时确实变红 |
| "动画推进的节点要单独加脏区" | 值变化会改变图元，`compute_damage` 已按节点取指纹；那段代码删掉后测试**仍然全绿**，说明它从未生效 | 按 §7.6「临时破坏看是否变红」时，破坏的是这段，结果没红 |
| "`AnimStore::advanced()` 是落定帧契约的一部分" | 契约真实存在，但实现位置不在那里：脏区由指纹比对产生，平台排帧由 `is_animating()` 回答。`advanced`/`ids` 只剩测试在测自己 | 追调用方时发现框架一次都没读它 |
| "时间推进可以放在 `view` 之后" | 重定向发生在 `view` 内，先 `view` 后推进会让值迟一帧才动；测试因此断言在第一帧失败 | 集成测试红在「移动了的帧必须有脏区」 |
| "`info.hovered` 就是「我被悬停」" | 它是**最上层**节点。卡片里铺满不透明子节点时，`card` 永远不被报告，淡入几乎不触发；点击语义必须保持最上层，容器的问法要另给祖先路径 | 用户报告「淡入效果我似乎没看到」；日志里 `hovered` 是子节点 id |
| "改了 CPU 循环就等于改了样例" | 样例有 CPU 与 GPU 两条循环，用户跑的是 GPU 那条；我只给 CPU 喂了 `dt`，GPU 仍在用不带时间的 `build`，动画永远停在第 0 帧 | 加诊断打印 `dt` 才发现恒为 0.00000 |
