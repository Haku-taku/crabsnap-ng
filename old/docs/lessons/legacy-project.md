# 旧项目材料：默认不可信

> 从 `AGENTS.md` §1.1 / §1.3 / §1.4 迁出。**原则与判据在 `AGENTS.md` §1**（三条采信通道、
> `[未证实]` 标注要求）；本文只放**分类规则**与**已发现的案例**。
>
> 背景：旧项目 `/home/ollie/git/crabsnap` 的笔记、计划、代码、注释存在**系统性**事实谬误。
> 不是"可能有小错"，而是已知在"接错开关"与"分层注释与代码不符"这两类事上会错。

## 1. 分类处理

| 旧项目的材料 | 默认状态 | 采取的动作 |
|---|---|---|
| `docs/notes/*.md`（200+ 篇"真机症状"笔记） | **未经证实的轶事** | 只有当它能被**新仓库里的代码/测试/真实 API 文档**独立复现时，才作为设计输入 |
| `TODO.md` / `DONE.md` / `PERF-TODO.md` / 计划文档 | **可能是错的路线图** | 不作为需求来源；需求来自用户与真实行为 |
| 源码注释（`//` / `///`） | **作者当时的理解，可能已过时或搞错** | 读代码本身；注释只在能对照出证据时采信 |
| 源码本身 | **在用的实现，但可能带缺陷** | 参考其**问题域**与**边界情形**，不默认其解法正确 |
| `docs/tech-selection.md` 等选型文档 | 待核 | 版本号与依赖清单要对照 `Cargo.toml` 与 crates.io 实际版本 |

## 2. 写作约定

- 引用旧项目内容时，**不允许**写成"旧项目证明/已记录/结论是"。
  正确写法是"旧项目 *声称* X（`path:line`），**待验证**"，或"**新仓库已核实**：X"。
- 迁移清单里凡是"照搬"的条目，必须能回答：**凭什么相信它是对的？**
- 若发现旧项目某条论断是错的，**记一笔**（`docs/decisions/` 下的 ADR 或本表），
  并说明"错在哪、我们怎么发现、正确做法是什么"——这样后来人不会重新踩。

## 3. 已发现的不信任案例（持续累积）

| 旧项目说法 | 实际情况 | 发现方式 |
|---|---|---|
| `pixelated()` 用于编辑态 | 反过来：编辑态判据是几何事实，与显示偏好无关 | 读源码发现 `nearest` 字段从未被置真 |
| `core` 是"不依赖任何业务模块"的最底层 | 实际有一处 `core::color` → `platform::wayland` 的反向引用 | 依赖图扫描 |

> 追加条目的门槛同 `docs/lessons/design-errors.md`：**非显然**、**重复遇到或代价足够大**、
> **具体到能照做**，且「发现方式」是一次可复现的观测。
